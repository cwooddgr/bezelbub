## What changed (user-visible, both apps)

- A Padding menu in the controls bar: None, 5%, 10%, 15%, 20%, or 25%. The percentage is of the bezel's longer side, added on every side. The choice is remembered across launches. Padding applies to screenshots and to video exports.
- Screenshots now have the Background color picker and Transparent switch that only video had before. Screenshots stay transparent by default. The color fills the padding.
- With a transparent background and padding above zero, the preview shows a checkerboard behind the image.
- Export sizes (Save, Copy, Share, and the size fields) include the padding.
- Not in the share extension: it frames with no padding and a transparent background, as before.
- Pricing is unchanged.

## Approved App Store text

What's New (both platforms):

```
• You can add padding around the device now. Pick 5%, 10%, 15%, 20%, or 25% from the new Padding menu, and Bezelbub will remember your choice next time.
• Screenshots get the same Background color picker and Transparent switch that videos already had. Pick a color and it fills the padding too.
• With a transparent background and padding turned on, the preview shows a checkerboard so you can see where the image ends.
```

Promotional text (both platforms): "Now you can add padding around the device and give screenshots a background color."

## Shipped the same day outside the App Store

- bezelbub CLI 1.5.0 (`cli-v1.5.0`, Homebrew tap updated): `frame --padding <N%|Npx>`, applied before `--output-size`.
- MCP server 0.4.0 (npm and the official MCP registry): optional `padding` on `frame_image` and `frame_video`; also the stale-session update notice from the unreleased 0.3.0. Clients need a restart or reconnect to see the new field. Smithery refused the update (403, "Updating servers has been removed"), so Smithery still lists 0.2.1.
